# 实盘执行 SOP

> 建这份文档的原因：项目有 170 篇研究报告、129 条运行记录、**0 笔真实成交**。
> 所有回测共用的 `SLIPPAGE_BP = 40` 是拍的，没有任何成交数据支撑，而它占单笔成本 78.6%。
> 在拿到真实滑点之前，任何"策略改进"的效果都无法与执行误差区分开。

---

## 一、一个调仓日的完整流程

| 步骤 | 时间 | 动作 | 命令 |
|---|---|---|---|
| 1 | T 日收盘后 | 跑数据与信号 | `python scripts/run_pipeline.py` |
| 2 | T 日 22:00 前 | 生成成交模板 | `python scripts/fill_log.py new --legs lowturn,cb` |
| 3 | 同上 | 看可下单清单 | `python scripts/fill_log.py list --date <T+1>` |
| 4 | T+1 日 09:15–09:25 | 集合竞价挂限价单 | 券商 App |
| 5 | T+1 日收盘后 | 回填真实成交价 | 改 CSV，或先 `fill --mode open` 再逐笔覆盖 |
| 6 | 同上 | 看执行进度 | `python scripts/fill_log.py status` |

**T+1 是"信号日的下一个交易日"，不是日历次日。** 遇周末顺延（例：11-06 周五出信号 → 11-09 周一执行）。

## 二、分批建仓：为什么先只做两条腿

30 万本金下，四条腿的每笔金额差一个量级，最低佣金 5 元造成的费率差 4 倍以上：

| 批次 | 腿 | 笔数 | 金额 | 佣金 | 费率 |
|---|---|---:|---:|---:|---:|
| **第一批** | 低换手 + 可转债 | 20 | 119,473 | 100 | **8.4bp** |
| 第二批 | 主策略 | 40 | 53,851 | 200 | **37.1bp** |

**主策略腿的金额只有第一批的 45%，佣金却是第一批的 2 倍。**

原因是 `regime_coeff = 0.45`——主策略腿当前只投 45% 预算，12 万变 5.4 万，
再摊到 40 只，每笔只剩 1,300 元，5 元最低佣金就是 38bp。
这是策略择时和最低佣金撞在一起的结果，不是配置错误。

所以**先做第一批**，理由是：

- 20 笔一天能填完，行为上可行；40 笔小额单容易半途放弃
- 8.4bp 的成本可忽略，第一天就能拿到干净的滑点样本
- 低换手腿是四条腿里 Sharpe 最高的（0.729，主策略 0.691）、MaxDD 第二好（−12.0%）、
  beta 最低（0.20）——**最好的一条腿恰好也是最好执行的那条**

主策略腿不是不做，是**放到第二批**：先证明 20 笔能跑完，再上 40 笔。

## 三、下单细则

**限价单，不用市价单。** 建议限价 = 参考价 × 1.02（`list` 命令已算好）。

- 开盘价高于限价 → **放弃该笔**，在 `note` 写 `未成交:高开`。
  放弃的代价是少一个持仓，硬追的代价是买入成本永久劣化，后者更贵。
- 参考价用的是**信号日收盘价**，不是当日开盘价。两者差异就是回测已经吃掉的隔夜跳空。
- 转债按**张**计（1 张 = 100 元面值），沪深都是 10 张起。

## 四、回填规则（最重要的一节）

`filled_px` 有三种合法状态，**不要为了好看而伪造**：

| 实际情况 | `filled_px` | `filled_shares` | `note` |
|---|---|---|---|
| 按计划成交 | 券商回报的**成交均价** | 实际成交数量 | **留空** |
| 部分成交 | 成交均价 | 实际数量 | `部分成交` |
| 未成交 | **留空** | 留空 | `未成交:高开` / `未成交:停牌` |

只有 `note` 留空的行才进入**实测滑点**统计。填了 `批量回填` 标记的行会被单列，不计入校准。

**`fill --mode open` 是账本对齐工具，不是校准工具。** 按开盘价回填算出的滑点恒为 0，
那不是实测值——真实执行只会比 0 更差。它的用途是"我知道我买了，但懒得一笔笔填均价"时，
先把持仓账本对上；之后有空再逐笔改成真实价。

**全部没执行时，什么都不要填。** `status` 会显示"未执行"，这是有用的信息；
用 `fill` 伪造成已成交，会让滑点统计永久失真。

## 五、什么时候算"闭环跑通"

预登记判据（在拿到数据之前写死）：

| 编号 | 判据 | 阈值 |
|---|---|---|
| E1 | 真实成交笔数 | ≥ 40 笔（含至少 4 个不同交易日） |
| E2 | 覆盖率 | 计划笔数中真实成交 ≥ 70% |
| E3 | 滑点 95% CI 半宽 | ≤ ±20bp |
| E4 | 与代理估计的一致性 | 实测中位数落在 `proxy` 给的区间内 |

E3 是核心：n < 20 时单笔噪声可达 ±50bp，bootstrap 的 CI 会有 ±30bp 以上，得不出结论。
40 笔是能压到 ±20bp 的最少样本量。

## 六、常见错误

- **用错交易日**：信号日 11-06 的模板，交易日是 11-09。别拿 11-06 的开盘价当成交价。
- **信号过期还执行**：模板生成后超过 2 个交易日未执行，直接作废重生成
  （挪到 `journal/fills/_void/` 并写作废原因），不要用旧价下单。
- **两个文件混填**：`fills_<日期>_lowturn-cb.csv` 和 `fills_<日期>_main.csv` 是两批，
  分别回填，`status` 会分别显示进度。
- **改了 `plan_shares` 却不改 `filled_shares`**：`report` 用 `filled_shares` 算金额权重，
  两者不一致会导致加权滑点算错。

## 七、命令速查

```bash
# 看今天该做什么
python scripts/fill_log.py status

# 生成某批模板（不给 --legs 就是四条腿全生成）
python scripts/fill_log.py new --legs lowturn,cb

# 打印可下单清单（含建议限价）
python scripts/fill_log.py list --date 2026-11-09

# 懒人回填：先对齐账本（滑点恒为 0，不进校准）
python scripts/fill_log.py fill --date 2026-11-09 --mode open

# 真·校准：累积 40 笔真实成交价后
python scripts/fill_log.py report

# 免5的券商，把最低佣金改成实际值再估费率
python scripts/fill_log.py list --date 2026-11-09 --min-fee 0.1
```
