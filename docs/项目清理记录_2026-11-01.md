## 2. 压缩归档的原始数据（5,452.9 MB → 1,006.1 MB，省 4,446.8 MB）

`build/alt/` 下 8 个另类数据原始抓取文件用 gzip 压缩。**不是删除，是无损归档。**

| 文件 | 原始 | 压缩后 | 压缩率 |
|---|---:|---:|---:|
| flow_raw.jsonl（资金流） | 3,878.7 MB | 678.5 MB | 17.5% |

| lift.jsonl（限售解禁） | 5.7 MB | 0.8 MB | 14.0% |
| dividend_raw.jsonl（分红） | 3.1 MB | 0.2 MB | 6.2% |
| **合计** | **5,452.9 MB** | **1,006.1 MB** | **18.5%** |

**为什么压缩而不是删除**：`reports/全量另类数据实测报告.md` 把"5 个数据源全部打通、5.4 GB 原始数据"
列为该次实验最实的产出。重爬成本高（1900 万条资金流 + 2435 天两融），且数据源可能限流或失效。
对应的 `*_panel.npz`（210 MB）已独立存在，日常建模不需要原始文件。

**无损性已验证**：
- 8 个归档全部通过 `gzip -t` 完整性校验
- 抽取 `lift.jsonl` 与 `dividend_raw.jsonl` 做「压缩 → 删除 → 解压」全流程，
  **md5 与原始文件逐字节一致**（`5da242ad8829f52923cb7143b10944f4` / `f5eac8d7c1e763d24c0b912c31dbcdf9`）

**如何恢复**：

```bash
python scripts/alt_restore_raw.py --list              # 查看归档状态
python scripts/alt_restore_raw.py --restore flow_raw  # 解压单个
python scripts/alt_restore_raw.py --restore-all       # 全部解压
python scripts/alt_restore_raw.py --pack              # 用完后重新压缩
```

`build/alt/README.md` 记录了目录结构与数据源明细。
