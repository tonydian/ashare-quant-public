# 因子池缓冲机制（防抖动）

> 2026-10-27；解决"数据微变导致因子池换人 → CAGR 波动 0.9pp"的问题。

## 一、问题回顾（已实测）

### 1.1 现象

| 版本 | CAGR | 说明 |
|---|---:|---|
| 含黄金 | 8.77% | 虚高 |
| 去黄金 | 8.05% | 真实 |
| 修 bug 后 | 8.87% | 真实 |
| **用 ext 数据** | **6.52%** | **掉了 2.35pp** |

### 1.2 归因结论（三个实验）

| 实验 | 结果 |
|---|---|
| E1 只延长区间（10-14 → 10-26） | **-0.04pp**（可忽略） |
| E2 多出 8 天的表现 | 策略 **+0.094%/天**，同期基准 **-3.53%** |
| E3 去掉尾部 1~5 个因子 | CAGR 在 **6.73%~7.41%** 波动（**±0.9pp**） |

**结论：2.35pp 的下降主要来自因子池重选，不是数据本身。**

### 1.3 根因：因子池尾部 |ICIR| 太接近

| 排名 | 因子 | \|ICIR\| |
|---:|---|---:|
| 28 | directional:R679 | 0.430 |
| 29 | risk-pattern:R737 | 0.411 |
| 30 | risk-pattern:R738 | 0.411 |
| 31 | risk-pattern:R473 | **0.384** |
| 32 | risk-pattern:R474 | **0.384** |

**彼此只差 0.05 —— 数据微变就换人。**

## 二、解决方案：挤占式缓冲

### 2.1 核心设计

```
第 1 层：连续确认（need_streak = 2）
  · 想进池的因子：连续 2 次重估都在应然池内 → 才真的进
  · 想踢出的因子：连续 2 次重估都跌出退出线 → 才真的踢

第 2 层：双阈值（防抖）
  · 入场线 entry_rank = k × 0.75（新因子要排进前 75%）
  · 退出线 exit_rank = k × 1.25（旧因子要跌出前 125% 才危险）
  · 之间的灰色地带 → 保持现状

第 3 层：极强因子直通（防僵化）
  · 排名 <= k × 0.5 的因子 → 立即纳入，不受 streak 限制
  · 保证真正变强的因子不会被缓冲卡住

第 4 层：挤占机制（防卡死）
  · 池满时，新因子达标就挤掉池内排名最差的
  · 不再依赖"先有空位"
```

### 2.2 状态持久化

```json
// build/models/_pool_guard_state.json
{
  "state": {
    "volume-stat:R716": {"in_streak": 2, "out_streak": 0},
    "risk-pattern:R081": {"in_streak": 0, "out_streak": 1},
    ...
  },
  "history": [   // 最近 20 次记录
    {"at": "2026-10-27T20:52:21", "pool": [...], "n": 34}
  ]
}
```

## 三、验证结果

### 3.1 逻辑正确性（模拟测试）

| 测试 | 结果 |
|---|---|
| 首次构建取前 k | ✅ |
| 池大小恒等于 k | ✅ |
| 排名不变 → 零换手 | ✅ |
| 小幅噪声 → 换手显著降低 | ✅ **3.0 → 1.2（-60%）** |
| **真正变强的因子能进池** | ✅ **第 1 次就进** |
| 移除需连续确认 | ✅ 单次跌出不踢 |
| 状态持久化 | ✅ |

### 3.2 真实数据验证（连续 3 次重训）

| 次数 | 换手 | 说明 |
|---|---:|---|
| 第 1 次 | 10 | 首次建立状态（保留 29、换 5） |
| 第 2 次 | **30** | ⚠️ 状态从无到有，大幅调整一次 |
| 第 3 次 | **0** | ✅ **完全稳定** |

**关键结论：第 2 次之后完全稳定（数据不变时零换手）。**

### 3.3 效果对比

| 场景 | 无缓冲 | **有缓冲** |
|---|---|---|
| 10 次数据微变累计换手 | 30 个 | **12 个（-60%）** |
| 数据不变时换手 | 可能非 0 | **0** |
| 强因子响应速度 | 立刻 | **立刻**（极强直通） |
| CAGR 抖动预期 | ±0.9pp | **约 ±0.3pp**（估计） |

## 五、局限与注意事项

### 5.1 第 2 次会大幅调整一次

因为第 1 次没有任何状态基线，第 2 次才建立"谁该进/该出"的连续计数。

**建议**：如果介意这次调整，可以在首次启用时手动跑两次（第二次的结果作为基线）。

### 5.2 代价：对真实变化的响应变慢

- 普通变化：需要连续 2 次确认（约 2 个季度）
- **极强变化**（排名前 50%）：立即纳入，无延迟

### 5.3 还没在真实"数据更新"中验证

本次验证是"数据不变重复跑"，证明了**幂等性**。

**真正的考验是未来几次真实数据更新**：需要观察
- 每次更新后池换手多少（期望 < 5 个）
- CAGR 波动幅度（期望 < 0.5pp）

**建议累积 4~8 次真实更新后再评估。**
