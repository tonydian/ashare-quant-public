# 交互与操作审计报告

> 2026-10-25；实测所有接口响应时间 + 逐个走查用户旅程。
> **结论：核心页面响应很快（<0.1s），但有 3 个真实痛点直接影响日常使用。**

## 0. 一句话总结

| 维度 | 状态 |
|---|---|
| **页面响应速度** | ✅ **优秀**（10/11 接口 < 0.1s） |
| **冷启动** | 🟡 35 秒（有提示但无分阶段进度） |
| **「今天买什么」能否带走** | ❌ **不能**（今日推荐页没有导出按钮） |
| **能否记录实盘执行** | ❌ **不能**（无界面） |
| **数据过期能否发现** | ❌ **不能**（无警示） |
| **异常标的响应** | ⚠️ **29.7 秒**（域外股票每次重算） |

## 二、5 个交互断点（按影响排序）

### ❌ 断点 1：查个股，域外标的要等 30 秒

**现象**：搜索茅台（600519）、或任何价格 >200 元的股票，**每次都要等 29.7 秒**。

**根因**：`stock_detail` 对域外股票会调用 `live_scores`（全市场 5281 只 × 34 因子重算），
而域内股票走了 `recommend` 的缓存。

**影响**：用户搜一只股票等 30 秒 → 直接放弃使用。

**修复方案**（成本低）：
1. 对 `stock_detail` 加 LRU 缓存（按 code + asof + model 缓存，TTL 到下一个交易日）；
2. 或者：域外股票直接跳过打分（返回"不在选股域"），**不做全市场重算**；
3. 后者更合理——反正域外股票本来就不该有分数（本轮已验证：因子层面对域外股票全是 NaN）。

### ❌ 断点 2：今日推荐页没有导出按钮

**现象**：看完了"今天买 36 只股票、143,312 元"，但**没法带走**——要手抄，或者去命令行跑脚本。

**现状**：后端有 `/api/recommend/export`（CSV 导出），但**今日推荐页没接**（只有已被删掉的旧推荐页有）。

**修复**：加一个"导出今日清单 CSV"按钮，一行代码的事。

### ❌ 断点 3：没有"实盘执行"的记录入口

**现状**：
- 后端 `daily_signal.py` 支持 `--holdings current_holdings.csv`（算相对当前持仓的订单）
- 但**网页没有任何入口**，用户无法录入自己的持仓

**影响**：无法知道"我该卖什么"，只能看"目标是什么"。

**修复**：加一个持仓录入（简单的文本框，粘贴 `code,shares` 或上传 CSV），
后端已有能力，只差界面。

### ❌ 断点 4：数据过期没有警示

**现象**：页面顶部显示"数据日期 2026-10-23"，但**如果是 3 天前、1 周前，外观完全一样**。

**风险**：用户可能拿着旧信号下单。

**修复**：
- 计算 `距今交易日数`，>1 个交易日标黄，>3 个标红并显示"⚠️ 数据未更新，请先更新"；
- 或者在数据页加一个显眼的状态条。

### 🟡 断点 5：冷启动无分阶段提示

**现象**：35 秒里只显示"加载中…"。

**修复**：`/api/meta` 已返回 `server.loaded` 状态，可以细化成：
- "正在加载行情数据…"（0-15s）
- "正在预热模型打分…"（15-35s）
- "就绪"（35s+）

## 五、一个更根本的交互问题

**当前系统是"查看型"的，不是"工作流型"的。**

正常的日常使用应该是：
```
打开 → 看到"今天做什么" → 一键导出 → 执行 → 记录执行结果 → 明天对照
```

现在是：
```
打开 → 看今日推荐 → 手抄/或者命令行导出 → 执行 → （没有记录环节）
```

**缺失的关键环节是"记录执行结果"** —— 没有这个，就永远无法：
- 知道实盘滑点是多少
- 知道涨停买不进的比例
- 验证回测假设是否成立

这也是上一份《项目改进建议》里"实盘对照记录"的交互层对应项。
