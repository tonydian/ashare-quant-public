## 7. 可复用的方法论（这轮沉淀下来的，别自己再发明）

### 7.1 "什么才算一个新维度"三判据

| # | 判据 | 阈值 |
|---|---|---|
| 1 | 与复合分相关 | \|ρ\| < 0.35 |
| 2 | 正交残差 IC / t | > 0.008 / t > 2 |
| 3 | **DEV→OOS 不衰减** | OOS ≥ DEV |

第 3 条是 2026-11 才加的，很关键：按 DEV ICIR 选池会选中 ep（0.0436→0.0221）、ROE（0.0467→0.0072），而 bp 是唯一"越往后越强"的。**没有这条，新维度会因为 DEV 排名不够而进不来。**

### 7.2 新因子的贡献上限（背下来，能省很多时间）

```
贡献上限 ≈ 权重 × 残差 IC
21 槽下新因子权重 ≈ 4.8% → 0.048 × 0.0127 = 0.0006 IC
OOS IC 标准误 SE = mean/ICIR/√n = 0.0867/0.723/√233 = 0.0079
→ 0.0006 / 0.0079 = 0.08 个标准误
```

**结论：单槽新增因子在统计上不可测。** 想测出价值，必须拿 15%+ 权重（要求 IC≈0.08 且 ρ<0.3，池外不存在），或者整族进。

### 7.3 IC / 分组统计 与 组合收益 的换算陷阱

- **分组十分位统计推不出组合幅度**，实测差 **6~11pp**（集中度、持有期、行业上限、节流、幸存者偏差）
- **IC 涨 ≠ 收益涨**：IC 由全截面中间分布决定，组合只买 top40。四次撞墙记录见 §0 铁律 2

### 7.4 相位带怎么做

8 个 `offset % 5 == 0` 的相位（offset 0/5/…/35，40 日调仓），同一份分数跑 8 次回测。报 **均值 / 中位 / 最差 / 胜率 / 配对 t**。生产相位 offset=10。

**单点最优陷阱已出现 5 次**：bp 落地、族预算（8.71% 是 8 相位最高）、族上限 cap0.20（9.17% 是最高）、板块轮动（11.89% vs 均值 9.46%）、信号合成。**看到"改完生产相位变好"先怀疑。**

### 7.5 闸门模板（写实验前先写这个）

```
相对基线需同时满足：
① 8 相位均值不降
② 最差相位不降
③ 决定性对照实验（"降仓位/买指数"能不能达到同样效果）
④ 剔除最好一年后仍为正
```

第 ③ 条是这轮最有用的发明（独立价值腿就是被它一击致命的）。

### 7.6 组合层方法论（2026-11-05 沉淀）

前三节都是"造更强的单腿"，这一节专治"组合层"。四条判据：

1. **相关性必须报三口径**：原始 / 相对基准超额 / 对基准回归残差。
   ⚠️ **减基准不会自动揭示负相关**。本项目实测：四腿原始相关 +0.303，减掉市场后
   **升到 +0.756**（同为 A 股多头，残余偏离高度同向）；只有残差口径（+0.124）才是真实分散度。
   招商报告能拿到 −0.16，是因为它两条腿**构造上对立**（追动量 vs 买冷门），不是减法的功劳。
2. **优化器输出先看有没有 0 权重，有就弃用。** 零权重意味着"该资产在这段没赚钱"（状态），
   不是"该资产不好"（结论）。实测：val 段网格最优把低换手设置为 0%，OOS 夏普从 0.721 掉到 0.538，
   **比不做优化的实盘还差**。
3. **"差异 < Npp"的断言前先问：如果两边都对，差异应该多大？** 答不上来就改成逐项比对口径。
   （同 §8-17）
4. **优化能不能用，看"能不能实现"，不看"优不优"**：一次性格网选优 −0.18 Sharpe（有害）；
   滚动重估 ±0.03（无信号）；固定人工权重最稳。**在 1,643 个样本点上，Sharpe 标准误约 ±0.05，
   0.03 以内的差异都是噪声。**

配套脚本：`build/eval_combo_frontier.py`（8 节：单腿 / 三口径相关 / 分散化红利 / 风险预算 /
网格前沿 / 滚动优化 / 分区间 / 逐腿剔除）。

## 8. 已知坑（都是踩过的，会重复踩）

1. **`pool_guard` 会吃掉因子数**：`k = min(len(prev_pool), max_factors)`。改 `max_factors`（如 20→21）时，若 `build/models/_pool_guard_state.json` 还记着旧的 20，新模型只会选 20 个。做法：把旧模型目录移走（走 initial 分支），跑完核对池与实验池逐项相同。

18. **✅ 组合侧「预算归一化」把 regime 系数抵消掉了（2026-11-05 修）** —— 静默、无报错、
    只在人类对照回测时才会发现，是这类 bug 里最难抓的一类。
    - **现象**：`latest_signal.json` 说主策略投 45%，`latest_combo.json` 里主策略腿投 50%。差 11%。
    - **根因**：`daily_signal.py::_build_combo` 用 `scale = main_alloc / base`，
      `base = sum(latest_target.csv 的金额)`。而 target 里的金额**已经乘过 regime**（0.45），
      所以 `base ≈ 0.45 × 本金`。缩放回 50% 预算恰好把 0.45 除掉 → 该腿又变成满仓。
      回测里 50/50 那条腿只有 **22.5%** 在股票、另 27.5% 在国债；实盘是 50%。
      **实盘比回测激进一倍多，`−6.93%` 的回撤是打了折的。**
    - **修法**：`main_cap = 腿预算 × invested_pct`，`scale = main_cap / base`；补仓上限也从
      `main_alloc` 改为 `main_cap`（否则「补余量」那一步会把腿重新填满，bug 从后门回来）。
      新增 `combo.main.invested_ratio / regime_coeff / target_alloc / leg_cash_pct` 四个字段。
    - **测试**：`test_combo_main_keeps_regime` 断言
      「combo 里主策略腿的投入比例 == `latest_signal.json` 的 `invested_pct`」（±2%）。
      这是**不变量**断言，不是数值断言——以后改预算、改权重都不会误报。
    - **同批修掉的第二处**：等额腿（低换手/板块）直接 `int(每份/lot)*lot`，
      10 只 × 9,000 元在 100 股整手下合计浪费 **8.2%（2.5% 本金）**。改为
      `_size_equal_legs()`：向下取整后把余量补回缺口最大的标的，单只超配上限 +10%。
      低换手腿实测从预算的 91.8% 提到 **99.4%**。
    - **教训**：「把某个子组合拉到满预算」这类归一化，必须先问一句
      **这笔钱里是否已经含有仓位系数**。凡是「比例 × 比例」的链条，
      中间任何一次重新归一化都会静默吞掉上游的比例。

    - 实盘 `_etf_trend_signal()`：只取**第一个**突破标的，按**整腿预算**买满。
      即「只有 1 只突破」时实盘仓位是回测的 **2 倍**，而这正是 90% 时间的状态。
    - 修法：抽出 `_size_etf_leg(picks, budget, max_pos=2)`，每只固定 `budget/max_pos`；
      `combo.etf` 新增 `legs` 列表（`leg` 保留为第一个，兼容旧消费方）。
    - **教训**：`MAX_POS` 这类"策略参数"散落在回测脚本里时，实盘很容易漏实现，
      而且**页面上还写着 2 只**（`test_etf_card_text_updated` 一直绿），
      形成"文档说 2、回测跑 2、实盘买 1"的三方不一致。
      判据：任何在回测里出现、且会改变仓位的常量，都必须在实盘代码里有一处对应引用
      或被测试直接断言，否则它迟早会漂移。

20. **整手容差是个比率，但「一手」的大小随品种变（2026-11-05）** —— 转债腿。
    - 股票腿 10% 容差够用：一手 600 元 / 单只预算 9,000 元 = 6.7%。
    - 转债腿 10% 容差完全不够：一手约 1,100 元 / 单只预算 3,000 元 = **37%**，
      300 元的容差连一手都跨不过去 → 每只卡在 2 手，整腿只投 **90.3%**。
    - 放到 25% 后：**97.7% → 98.8%**。代价是等权被破坏（2 手 vs 3 手 = 1.5 倍）。
    - 同理，`latest_combo.json` 的转债段单位是**张**（`shares`），前端做「买入/卖出
      多少」的差异判断时，步长必须按 `unit` 分开（股/份 100、张 10），否则转债会显示
      「买入 0」或「买入 110 张」。
    - **教训**：凡是「超配比例」「最小变动单位」这类参数，都要同时问一句
      **分母是什么**。分母从 9,000 变 3,000、粒度从 100 股变 10 张，同一个 10% 就从
      "略紧"变成"根本跨不过去"。判据：换品种时先算 `一手成本 / 单只预算`，
      超过 15% 就必须调容差或减持仓数。

21. **管道阶段顺序 = 隐式数据依赖（2026-11-05）** —— `cb_signal` 与 `signal`。
    - `signal` 阶段要读 `signals/latest_cb_signal.json` 建转债腿，但 `cb_signal`
      原本排在它**后面** → 每天用的都是前一天的榜单，而且**不会报错**。
    - 修法：把 `cb_signal` 移到 `signal` 之前，并加测试
      `test_pipeline_cb_signal_runs_before_signal` 断言两个阶段在 `STAGES` 里的先后。
    - **教训**：`STAGES` 列表的书写顺序就是数据流顺序，但它在代码里长得像"配置"。
      只要有阶段 A 读阶段 B 的产物，就必须有一条测试钉住 A 在 B 之后，
      否则重排列表（看起来无害）会静默降级成"用昨天的数据"。

22. **组合权重枚举：上界写成「剩余份额」，会切掉一整个区域（2026-11-05）** —— 坑 17 的同类。
    - `eval_combo_frontier.py::_maxsharpe_nooptim`：
      `for b in range(capn+1-a)` / `for c in range(capn+1-a-b)` → `a+b+c ≤ capn`，
      而 `d = g-a-b-c` → **第 4 条腿权重被强制 ≥ (g-capn)/g = 40%**。
      枚举点从 1291 缩到 **335**，把"第 4 腿低配"的整个区域切掉了。
    - 该函数目前是**死代码**（只定义、从未被调用），所以
      `四条腿组合层与有效边界_2026-11-05.md` 的结论未受影响；已修成与 `grid_scan` 同款上界。
    - 坑 17 是"漏掉大权重少腿组合"（前沿下限虚高 9.57% vs 实盘 6.78%），
      这个是"漏掉第 4 腿低配"，**同一个 bug 的两个方向**。
    - **教训**：这种错误**输出照样是一组合理权重**，肉眼看不出来。
      唯一可靠的判据是**枚举点数** —— 与已知正确的 `grid_scan` 对不上就是错了。
      判据：任何新写的权重枚举，先打印 `len(grid)` 和一条已知配置是否在集合内。

23. **面板是后复权价，任何"真实价格"用途都要先换算（2026-11-05）** —— 成交记录模板。
    - `panel_ohlcv.npz` 的 `close` 是**后复权**价（康力电梯 51.44），
      而信号里 `price` 是真实下单价（5.32）。直接拿面板价去填模板，
      人根本没法核对，也无法和券商成交单比对。
    - 修法：用信号日的 `后复权收盘 / 信号价` 求复权因子，把 T+1 开盘换算回真实空间。
      已用测试钉住：`ref_close` 必须 == 信号价（±0.01%）。
    - 顺带：`amount/volume` 是**原始价**空间的 VWAP，不能直接和 `close` 相除
      （踩过一次，样本数直接算成 0）。日内漂移只能用同为后复权的
      `open/close/high/low` 算。
    - **教训**：这个仓库里同名变量至少有三种价格空间（原始 / 后复权 / 复权净值）。
      判据：任何要跟外部对账的数字，先在代码里显式写一句"换算到哪个空间"。

24. **「相对基准超额」这个相关口径，只在 beta ≈ 1 时成立（2026-11-05）** —— 方法论纠错，修正坑 25。
    - 坑 25（招商双轮）得出的结论是"两腿相关性必须按相对基准超额算"，
      因为用原始收益会被市场 beta 主导，得到 +0.70 的假象。
    - 但四腿实测：原始平均相关 **+0.164**、减市场后 **+0.834** —— 反而更高。
      原因：各腿 beta 是 0.383 / 0.193 / 0.085 / **0.032**，减市场后每条腿都变成
      `(beta−1)·m + 残差 ≈ −0.9m + 残差`，共同的 −市场项把四条腿人为粘在一起。
    - **正确做法：统一用「对市场回归残差」**（`three_corr` 的第三个输出）。
      它对任何 beta 都成立：四腿残差平均相关 **+0.050**，转债 0.020/−0.003/0.008。
    - **教训**：坑 25 的规则不是普适的，它成立的前提是"两腿都是高 beta 的方向性策略"。
      凡是这类"用减法去掉某个共同因子"的技巧，都要先看被减掉的那一项**占每条腿多大比重**。
      判据：做相关分析前先打印各腿 beta；beta 跨度 >0.3 时只能用残差口径。
